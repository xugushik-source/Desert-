# DESERTO — Десерто — დესერტო

Площадка независимых кондитерских по городам. Независимый проект в репозитории `xugushik-source/Desert-`. Исходный SWEET HOUSE сохранён без изменений.

## Что реализовано

- Два тестовых города, три отдельные кондитерские, 36 исходных товарных карточек у каждой. Цены, остатки, варианты, расписание и вместимость интервалов принадлежат конкретной кондитерской.
- Витрина RU/KA/EN, поиск, категории, карточки, рекомендации дополнений, записка и получатель подарка. Отдельные сохраняемые корзины; очистку можно отменить.
- Один заказ относится к одной кондитерской. Смена города не переносит товары между продавцами. Время рассчитывается в часовом поясе города; целым тортам в тестовых данных требуется 24 часа.
- Серверный расчёт в целых тетри, проверка ожидаемой покупателем суммы, атомарное резервирование товаров и интервала. Повтор запроса с тем же ключом возвращает исходный заказ.
- Кабинеты владельца площадки, администратора кондитерской, сотрудника и курьера. Доступ через пароль и HttpOnly-сессию; приглашения одноразовые. Удалённый участник сразу теряет права.
- Подтверждение, подготовка, готовность, самовывоз; назначение курьера, получение, выезд и доставка. Второй курьер не может перехватить заказ. До назначения курьеру не показываются данные покупателя.
- Изменение состава и количества с причиной, первоначальным снимком и согласием покупателя. Изменение цены после предложения требует нового предложения.
- Отдельная запись проверенной оплаты, частичные платежи, долг, предотвращение повторного платежа. Доставка сама не подтверждает оплату. Отмена после начала приготовления списывает приготовленные позиции; предоплата переводится на проверку возврата.
- Управление городами и витринами владельцем, товарами и сотрудниками продавца, журнал событий заказа, показатели по завершённым заказам. Если себестоимость не задана, прибыль не выдумывается.
- События заказов записываются в outbox. Канал отключён: никаких ботов, рассылок и внешних платежей.

Все данные демонстрационные. Сведения о настоящих адресах, телефонах, остатках, себестоимости и аллергенах не придуманы. Имена продавцов и их присутствие в городе не подтверждают реальное партнёрство. Фотографии — оригиналы SWEETHOUSE-, происхождение в `public/media/ORIGIN.md`.

## Запуск без внешних сервисов

Нужен Node.js 24+. Зависимости для локальной работы и тестов не требуются.

```sh
git clone https://github.com/xugushik-source/Desert-.git
cd Desert-
git checkout feature/deserto-marketplace
npm test
npm run dev
```

Открыть `http://127.0.0.1:5173`. Кнопка «Кабинет» открывает вход. Случайный пароль владельца и локальный ключ восстановления создаются в `.runtime/local-access.json` с правами 0600. Они не выводятся в лог и исключены из Git. Данные переживают перезапуск в `.runtime/deserto.sqlite`. В кабинете владелец выбирает кондитерскую и выдаёт приглашение её администратору через «Команда». Администратор приглашает своих сотрудников и курьеров.

Покупательский доступ к заказу хранится в этом браузере. Ссылки и ключи доступа нельзя передавать посторонним. Восстановление через SMS/email пока не подключено.

## Новое независимое развёртывание

Сайт не развёрнут этой веткой. Старый SWEET HOUSE, его GitHub Pages и ТЖВЖИК не переключаются на этот Worker. Для DESERTO предназначены отдельные Worker `deserto-demo` и D1 `deserto-db`; чужие базы использовать нельзя.

После авторизации Cloudflare и разрешения на размещение нового демо:

```sh
npm ci
npx wrangler d1 create deserto-db
```

Вставить UUID НОВОЙ базы в `wrangler.jsonc`, затем:

```sh
npx wrangler d1 migrations apply deserto-db --remote
node tools/prepare-database.mjs
npx wrangler d1 execute deserto-db --remote --file .runtime/bootstrap.sql
npx wrangler secret put RECOVERY_SECRET
npm run build
npx wrangler deploy
```

Для `secret put` использовать ключ из `.runtime/deploy-access.json`, через защищённый ввод; тот же файл содержит доступ владельца для новой базы. Не публиковать этот файл и SQL bootstrap. Bootstrap предназначен только для пустой новой базы, повторно не запускать. Потеря/смена `RECOVERY_SECRET` меняет выдаваемые при повторе запроса ключи заказов, поэтому ключ нужно хранить надёжно. Случайные пароли в репозиторий не попадают.

10. Отмена освобождает резерв; устаревшая команда не изменяет данные; внешние уведомления отключены.

## Исправления при проверке

Исправлены привязка параметров D1 при согласовании замены, обработка асинхронной ошибки входа, расчёт срока подготовки через полночь, передача версии заказа для назначения курьера, повторное изменение цены уже предложенной замены, отсутствие первого товара у нового продавца, возврат с кабинета на главную, устаревшие позиции корзины перед оформлением и сохранение ключа повторной отправки между перезагрузками браузера.

Контракт D1 сверялся с [официальной документацией prepared statements](https://developers.cloudflare.com/d1/worker-api/prepared-statements/).

## Не выполнялось

- Браузерный E2E, скриншоты и визуальная проверка на телефоне: в этой среде недоступен поддерживаемый браузерный инструмент. Статическая адаптивная вёрстка, управление фокусом и отключение анимации реализованы, но это не заменяет проверки браузером.
- Удалённая D1, размещение нового Worker, живые клиентские заявки, деньги и сообщения.
- Telegram, Google Sheets и эквайринг: по текущему решению боты отключены; внешние интеграции не объявляются работающими. Outbox — сохранённые внутренние события с отключённым каналом, а не готовая отправка.
- Нагрузочная проверка, полноценный аудит перед публичной эксплуатацией и работа с настоящими продавцами.

GitHub Actions настроен для тестов и dry-run сборки без публикации. Наличие workflow не означает, что его запуск уже завершён успешно; результат проверяется отдельно на GitHub.

После запроса владельца изучены NN/g, Baymard и W3C. Обновлена светлая кремово-розовая палитра, численно проверены выбранные пары цветов (минимум обычного текста 4.76:1), повторная dry-run сборка успешна. Это не визуальное тестирование и не A/B-тест продаж. См. `DESIGN_RESEARCH_RU.md`.
