# Проверка DESERTO

Дата: 16 октября 2026. Node.js 24.19; Wrangler 4.92.0.

## Выполнено

`npm ci --ignore-scripts --no-audit --no-fund` — успешно, 37 пакетов.

`npm test` — 18 тестов, 18 успешных, 0 пропущенных. Тесты вызывают настоящий обработчик Worker API и выполняют SQL в отдельной SQLite-базе на каждый сценарий. LocalD1 повторяет немутирующее связывание параметров D1 и транзакционный batch; это не удалённая D1 и не браузерный E2E.

Проверены:

1. Города и независимые продавцы; отсутствие себестоимости в публичном каталоге.
2. Сохранение заказа, повтор того же запроса, защита от подмены клиентской суммы и неправильного ключа доступа.
3. Отклонение чужого города и товара другого продавца.
4. Конкуренция за последний товар: один успех, второй запрос отклонён; нет потерянных резервов и незавершённых заказов.
5. Конкуренция за последний интервал; откат резервов при неудаче.
6. Аутентификация, CSRF, изоляция кабинетов, отсутствие доверия подставленному заголовку пользователя, выход.
7. Одноразовое приглашение и невозможность самостоятельно назначить себе роль владельца.
8. Полный самовывоз: создание → подтверждение → частичный платёж → окончательный платёж → подготовка → готовность → выдача. Повтор платёжной команды не создаёт второй записи; переплата отклоняется; остатки и выручка обновляются.
9. Замена: исходный состав сохраняется до согласия; неверный ключ и повторное устаревшее согласие отклоняются; первоначальный снимок сохранён.
10. Отмена освобождает резерв; устаревшая команда не изменяет данные; внешние уведомления отключены.
11. Расчёт времени Тбилиси и срока подготовки целого торта через границу суток.
12. Полная доставка: подготовка → готовность → две одновременные попытки назначения → один назначенный курьер → получение → выезд → вручение → отдельная проверенная оплата. Другой курьер не перехватывает доставку и не получает данные клиента.
13. Изменение цены после предложения замены не применяется автоматически; первоначальная сумма и резерв остаются целыми.
14. Только владелец добавляет город и скрытую кондитерскую; отключение сотрудника действует для уже открытой сессии.
15. Все ключи интерфейса присутствуют в RU/KA/EN, все фотографии из стартового каталога существуют.
16. Неверный пароль возвращает ожидаемый JSON-ответ, после десяти неудач вход временно ограничен.
17. Администратор новой пустой кондитерской создаёт первый товар из общей заготовки, с собственным остатком и ценой; копирование чужого закрытого каталога по идентификатору запрещено.
18. Нулевая сумма заказа не требует фиктивной платёжной записи.

`npm run build` — успешно: Worker 56.88 KiB, gzip 13.66 KiB; 41 статический файл; bindings DB и ASSETS. Использован `wrangler deploy --dry-run`: развёртывания не было.

## Не выполнялось

- Браузерный E2E, скриншоты и визуальная проверка на телефоне: в этой среде недоступен поддерживаемый браузерный инструмент. Статическая адаптивная вёрстка, управление фокусом и отключение анимации реализованы, но это не заменяет проверки браузером.
- Удалённая D1, размещение нового Worker, живые клиентские заявки, деньги и сообщения.
- Telegram, Google Sheets и эквайринг: по текущему решению боты отключены; внешние интеграции не объявляются работающими. Outbox — сохранённые внутренние события с отключённым каналом, а не готовая отправка.
- Нагрузочная проверка, полноценный аудит перед публичной эксплуатацией и работа с настоящими продавцами.

GitHub Actions настроен для тестов и dry-run сборки без публикации. Наличие workflow не означает, что его запуск уже завершён успешно; результат проверяется отдельно на GitHub.

После запроса владельца изучены NN/g, Baymard и W3C. Обновлена светлая кремово-розовая палитра, численно проверены выбранные пары цветов (минимум обычного текста 4.76:1), повторная dry-run сборка успешна. Это не визуальное тестирование и не A/B-тест продаж. См. `DESIGN_RESEARCH_RU.md`.

## Дополнение: акции и рост площадки — 16.10.2026

Добавлены шесть автоматических сценариев:
1. Точная граница 10%, округление вверх, обязательность каждой статьи расходов,
   отказ отрицательным суммам и игнорирование поддельной прибыли из браузера.
2. Изоляция продавцов, согласование только владельцем, откат при недостаточной
   доходности, фактическая цена заказа со скидкой, повтор команд и остановка акции.
3. Подарок сохраняется в позиции заказа как обещание исполнения.
4. Рейтинг учитывает завершённые оплаченные продажи и не учитывает отмены,
   неоплаченные заказы и другой город.
5. Полный самовывоз/отдельная оплата → фактические расходы → незакрытая недостача
   → исправленный расчёт с 10% → закрытие; дубли и чужой доступ отвергаются.
6. По одному торту без дублей в корзине; сохранение прежних позиций и паритет RU/KA/EN.

Применение добавочной миграции повторно сохраняет заказ и его сумму.
Реальных выплат, рассылок и клиентских данных тесты не используют.
Финансовое правило проверяет полноту и математику подтверждённых владельцем
данных; внешнего подтверждения налогов/издержек и гарантии прибыли нет.

Седьмой сценарий роста: нетестовый заказ блокируется без условий, ниже 10% не
создаёт заказ/резерв; продавец не может подменить условия; подходящий расчёт
сохраняется с заказом. При изменении условий до согласования замены проверка
срабатывает повторно и сохраняет первоначальную сумму. Всего 28 тестов.
